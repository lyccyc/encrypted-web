# VaultCipher

VaultCipher is a Python web app for encrypting and decrypting personal ID numbers in CSV and Excel spreadsheets. It provides a small Flask interface with upload forms, format-preserving encryption options, demo data, and downloadable spreadsheet outputs.

The app is configured for local development and Vercel deployment.

## Features

- Upload `.csv`, `.xlsx`, or `.xls` spreadsheets.
- Encrypt ID numbers with FF1 or FF3-1 format-preserving encryption.
- Download encrypted public output and metadata output as a ZIP file.
- Decrypt encrypted metadata/result files back into restored ID values.
- Try bundled sample data without uploading a file.
- Run as a Flask app locally or through the Vercel Python runtime.

## Requirements

- Python 3.10 or newer recommended
- A 32-character hexadecimal encryption key
- Spreadsheet input with an `ID` column

Install dependencies from `requirements.txt`:

```bash
pip install -r requirements.txt
```

## Environment Variables

Create a `.env` file in the project root:

```env
KEY=00112233445566778899aabbccddeeff
```

- `KEY`: 32-character hexadecimal key used by the encryption libraries.

## Usage

Use the deployed web app:

```text
https://fpe-encrypted-web.vercel.app/
```

For local development, run the app locally:

```bash
python api/index.py
```

Then open the local app in a browser:

```text
http://127.0.0.1:5000
```

Use the workspace:

1. Open `/workspace`.
2. Upload a CSV or Excel file with an `ID` column.
3. Choose `FF1` or `FF3-1` for encryption.
4. Download the generated ZIP file.
5. For decryption, upload the metadata/result spreadsheet generated by the encryption flow.

## How It Works

### Encryption Flow

1. `api/index.py` receives an uploaded spreadsheet from `/encrypt`.
2. The upload is saved into a temporary work directory.
3. `excel_to_csv()` converts the input file to CSV.
4. `encrypt_engine.encryption()` reads the CSV and processes each row.
5. Each `ID` value is converted into a numeric representation.
6. The selected crypto helper is used:
   - `app/crypto/ff1_lib.py` for FF1
   - `app/crypto/ff3_lib.py` for FF3-1
7. The engine writes two CSV files:
   - `encrypt_<algorithm>_<filename>.csv`: public encrypted output
   - `meta_<algorithm>_<filename>.csv`: metadata needed for decryption
8. Both CSV files are converted back to Excel.
9. The Excel outputs are bundled into `result_<filename>.zip` and returned for download.

### Decryption Flow

1. `api/index.py` receives a metadata/result spreadsheet from `/decrypt`.
2. The file is converted to CSV.
3. `encrypt_engine.decryption()` detects the algorithm from the filename:
   - filenames containing `ff1` use FF1
   - filenames containing `ff3` use FF3-1
   - unknown filenames default to FF3-1
4. The encrypted numeric values are decrypted.
5. Numeric values are converted back into ID format.
6. The result is exported as an Excel file containing encrypted and decrypted ID columns.

## Input Format

The input spreadsheet must include an `ID` column.

Example:

```csv
ID
M210078175
F199096961
Q216973903
F280062477
N162998165
C916305800
B220210079
C180901536
H144948896
T219968185
```

The app currently supports IDs whose first two characters match the internal ID prefix mapping used in `ff1_lib.py` and `ff3_lib.py`.

## Output Files

Encryption returns a ZIP containing:

- `encrypt_ff1_<input>.xlsx` or `encrypt_ff3_<input>.xlsx`
- `meta_ff1_<input>.xlsx` or `meta_ff3_<input>.xlsx`

Decryption returns:

- `decrypted_<input>.xlsx`

## Deployment Notes

This repo includes `vercel.json`, which rewrites all requests to `api/index.py`:

```json
{
  "rewrites": [
    {
      "source": "/(.*)",
      "destination": "/api/index"
    }
  ]
}
```

When deploying to Vercel, configure `KEY` in the project environment variables. For public demos, set `PUBLIC_DEMO_MODE=true` so only bundled demo files are processed.

## Security Notes

- Uploaded files are processed in temporary runtime directories and cleaned up after the response closes.
- File names are sanitized with Werkzeug's `secure_filename()`.
- Upload size is limited to 4 MB.
- `.env`, temporary files, local upload/output folders, and Vercel metadata are ignored by Git.
- The metadata output contains information needed for decryption, so it should be handled as sensitive data.
